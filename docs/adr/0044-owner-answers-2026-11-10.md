## Context

On 2026-11-10 the owner answered the open questions from the 2026-11-09 batches and pointed at the old installed app as the concept reference. The installed older Flutter build (navigation still shows «الحساب») failed to open the daily ledger after the 2026-11-09 server changes added `day_reset`, `last_closed_business_date`, and repair keys inside `day_summary`. The parsers at commit `361ad2e` reject those extras. This record locks the answers and the compatibility rule so a later server change never breaks an installed older build again.

## Decision

C-D1. A server change must never break an installed older build. Public read RPCs that existed at commit `361ad2e` return exactly the keys that commit's client parsers accept. New fields go to new `_v2` reads that only the current app calls. Legacy wrappers strip the new keys and also keep the values that commit validates: its feed parser accepts only its own kinds and labels, so legacy feed rows show a repair as `repair_fee` «أجرة إصلاح» (a collection included) and omit kinds it never knew (debt and gold-obligation rows). Command payloads of that build stay valid: a field added to a command is optional, and leaving it out keeps the stored value. Server functions never call a legacy name internally; they call `*_full` or `*_v2`.

C-D2. The built-in jewelry items are the old app's names, plural, in the old app's table order: محابس، توينز، غوايش، سلاسل، انسيالات، حلقان، اساور، تعاليق، كوليهات، دبل، خواتم. جنيهات stays a category and is the first table row; سبائك and كسر stay categories. No other built-ins: the «أخرى» list drops every name not in the old app (خلخال، طقم، نص طقم، بروش، كف، ميدالية) and the singular forms. Merchants still add their own items.

C-D3. Existing data keeps its stored names. One canonical map joins them in reads and stock choice: خاتم→خواتم، حلق→حلقان، سلسلة→سلاسل، تعليقة→تعاليق، دبلة→دبل، محبس→محابس، غويشة→غوايش، إسورة→اساور، انسيال→انسيالات، كوليه→كوليهات. New lines are stored with the plural name.

C-D4. «الأصناف حسب العيار» always lists جنيهات then the 11 built-ins, with zeros when there is no stock, then custom items with stock, then «رصيد افتتاحي (بدون صنف)» when it has stock, then «كسر» and «الإجمالي».

C-D5. Replace the six figures with the old app's carousel, in its order: عيار 18، عيار 21، عدد السبائك، وزن السبائك، اجمالي النقدية، الكسر 18، الكسر 21، اجمالي الكسر 21، اجمالي الوزنة 21 (مشغولات + سبائك)، اجمالي الوزنة 21 (مع الكسر)، and «اجمالي الوزنة 21 مع النقدية», which shows «اضغط للحساب», asks «أدخل سعر الجرام», and shows the result. «عيار N» counts worked jewelry only; coins (جنيهات) are in no figure, as before. The owner did not ask for coins in these figures. Add عيار 22 / عيار 14 / الكسر 22 / الكسر 14 only when that karat has stock. The cash calculator is display only and saves nothing.

C-D6. After a close the ledger home shows the carried cash and zero for every daily figure, book, note, and expense. Gold and scrap balances are not on the home screen; they stay in «الجرد الفوري». This is the current behavior; lock it with a test.

C-D7. «الصيانة» becomes «المرمات» everywhere in the UI, the reports, the PDF, and the copy. One repair is «مرمة». Database names and RPC names stay. Collection timing does not change.

C-D8. After a coin or bullion line is confirmed on a purchase form, a half-height sheet asks «هل تريد إضافتها لمخزون الجنيهات؟» (or «السبائك»). «نعم» keeps the line. «لا» shows the karats (24 and 21 first, then 22, 18, 14) and turns the line into scrap at that karat with the same weight and no count.

C-D9. A customer has «في جروب الواتساب» (yes/no), set with VIP and open request, owner only, audited. It shows on the card, in the detail header, as a filter chip «جروب الواتساب», and as a quick action.

C-D10. Every customer phone field (customers, sale, purchase, repair) starts on the country of the shop owner's own registered phone. The picker stays for foreign numbers. The current country list already covers the Arab countries; keep it.

C-D11. The customer fields of a sale and a purchase are titled «العميل» on both («تفاصيل العميل (اختياري)», «اسم العميل (اختياري)»). The purchase capture hint says «العميل».

C-D12. No code change for the invoice header. The header prints `shops.name`. The owner corrects the test shop name in «المزيد ← بيانات المتجر».

Not in this batch: price per item on a trade, the default invoice message wording, the iPhone/desktop WhatsApp file flow, and ledger item-row count.

## Data and compatibility impact

Money stays integer piastres and gold stays integer milligrams. New migrations only, after `20261109120100`.

- `get_daily_ledger_home_v1`, `get_ledger_date_v1`, `get_financial_day_report_v1`, and `get_ledger_operation_page` keep the `361ad2e` shapes. Full payloads live as `*_full` internals and as public `*_v2` for the current app. `private.legacy_361ad2e_feed(jsonb)` puts legacy feed rows in that build's vocabulary (`20261110100400`). The home and week chains read the full date and day reads (`20261110100500`).
- `private.customer_status` accepts the `361ad2e` status payload without `in_whatsapp_group` and keeps the stored flag.
- `private.canonical_jewelry_name(text)` maps legacy singular names. `private.consume_fifo_named` and `get_inventory_item_grid_v1` group and match by the canonical name. The grid adds a «جنيهات» coin row.
- `public.customers.in_whatsapp_group boolean not null default false`. Status commands and customer reads carry the flag; the list gains filter `whatsapp_group` and overview `whatsapp_group_count`.
- `private.ledger_operation_label` and `private.audit_trail_action_label` use «أجرة مرمة» and «تحصيل متبقي مرمة» for repair fee kinds.
