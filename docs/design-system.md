Stale shared changes keep dirty drafts and require another review. Expired readers retain saved text; new writes are blocked. Access or token loss clears visible draft/preview without deleting recovery data. Appearance and message settings have separate invalidations; location/subscription changes still refresh access.

Opened never says sent or delivered; explicit owner confirmation remains on the operation screen. Native https cancellation is not observable. The legacy PDF and branded-copy controls remain separate.

Reuse Cairo, semantic brown/cream/dark roles, persisted themes and 48-pixel controls. Display-only isolates stabilize digits/times; stored templates and external bodies remain validated plain text. [Actual synthetic captures and review](reviews/invoice-messaging-2026-10-18/independent-validation.md) cover 320/390/1440, both themes and 1.0/1.7 text scaling. ## Layout and typography

Both clients use Arabic copy and RTL navigation with logical start/end spacing. Both clients bundle Cairo under the SIL Open Font License. Flutter registers it as Cairo; React loads its local font face with a Tahoma/Arial fallback. The license accompanies each bundled font. The common wide breakpoint is 840 logical pixels and main content measure is 720; auth uses a narrower 480-pixel form. Use 16-pixel phone gutters by default; the daily ledger uses the shared 12-pixel `ledgerPhoneGutter` at all widths below 840, following the owner's borderless-layout refinement. Use 48-pixel targets, soft card corners around 22 logical pixels, pill action chips, and persistent labels. Avoid truncating mixed Arabic text and phone/cash values. Respect text scaling, keyboard insets and reduced motion.

The shared type scale is 12/14/16/20/24 logical pixels for captions, supporting text, body/fields, section headings and figures. Headings use 700, labels 600, and body text 400. Cairo remains the common family. Tabular figures stabilize numeric layout; monetary text stays LTR inside the RTL interface. Use 1.5 line height and zero added tracking for Arabic text. The global Flutter input theme and React outlined-input theme share 14-pixel corners, 16-pixel field text, generous internal padding, semantic borders and a visible focus state. Authentication keeps the jewelry hero dissolving into the page color, with an elevated card, while sharing size and corner tokens.

## Verification rules

1. Read this guide and both token files before changing UI. Use semantic theme roles for text, surfaces, controls, borders, errors, pending and success.
2. Update both clients' tokens and this guide together for shared visual changes.
3. Review Arabic RTL in light and dark modes at narrow phone and desktop widths, including populated, error, pending, success, text-scale and keyboard states as relevant.
